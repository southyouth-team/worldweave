# 南昌工学院校园地标内置素材设计（rev.2，2026-11-12）

rev.2 变更（用户批准后补充并确认）：致远楼**一楼可进入、含数间 furnished 教室与灯具**；灯具接「人工灯光总开关」；二至五层维持外观实心、不做楼梯。执行方式沿用 **Native 内联执行**。

## 1. 背景与意图

内置素材库现有 13 件通用素材（植被/构筑物/设施/装饰/运动），没有任何与南昌工学院实景相关的内容。用户（本校学生）希望在沙盒里摆放自己学校的地标，先做**校门、教学楼、操场**三件。

已确认的需求决策（用户逐条答复）：
- 三件**独立素材**，用户自己摆放组合，不做整景预设。
- 外观以网上侦察到的官方实景为参考（用户授权搜索，已实际查看照片）。
- 延续既有原则：真实世界尺寸（1.7m 玩家基准）、低多边形 stylized 风格、完整碰撞声明。
- 致远楼一楼可进，有课桌椅/黑板/讲台的教室，灯具有真实光源并受环境总开关控制（rev.2）。

## 2. 目标 / 非目标 / 反目标

**目标**
- 三件可一眼认出「是南工」的地标素材：南工东大门、致远楼（教学楼）、天工体育场（操场）。
- 致远楼一楼可经真实门洞进入，走廊连通数间教室，教室内可走动、有家具阻挡、有可用灯光。
- 全部通过既有 `analyzeModelCollisionCompleteness` 门禁（complete、零 issue）。
- 模型管理面板新增「校园地标」分类，点击即进入既有放置流程。

**非目标（本期不做）**
- 整景预设、笃行楼、图书馆、望月湖、景明桥、宿舍楼群（已侦察留档，后续可扩展）。
- 致远楼二至五层内部、楼梯、电梯；未开放的一楼两翼（实心）。
- 看台登临（看台是阻挡体）；校门与操场的灯具/环境绑定（仅致远楼教室有灯）。
- 测绘级还原（无实测数据，尺寸为合理估算，见 §4）。

**反目标**
- 「任意一所学校都适用」的通用校门/教学楼——辨识度特征必须保留（§3 逐件列出）。
- 退回生成器注册表的 2m 立方默认比例。
- 空壳教室（有房间无家具）或不受总开关控制的灯。
- 放置操场时才让用户第一次发现需要扩地（卡片必须先提示）。

## 3. 实景依据与辨识度特征

侦察来源：招生网「美丽校园」官方图集（zsb.ncpu.edu.cn，照片已实际查看），辅以搜狗/360 搜索文字佐证。WebSearch/WebFetch 在本环境不可用，实际通过 PowerShell 抓取。

### 3.1 南工东大门（`campus:east-gate`，label「南工东大门」）
官方照片：古典中式门楼。必须保留的特征：
- 灰白门墩 + 棕红色瓦顶**三重檐**（中央高、两翼低的对称轮廓）。
- 正中央**黑底金字匾额「南昌工学院」**。
- 中央大拱门（可通行）+ 两侧小门洞。
- v1 简化：不做基座台阶与门前广场（避免台阶碰撞复杂度；广场由用户自行铺装），门墩直接落地。

### 3.2 致远楼（`campus:zhiyuan-building`，label「致远楼（教学楼）」）
官方航拍：超长条形多层教学楼。外观必须保留的特征：
- 长条板楼体量 + **白色竖向柱廊**（连续竖框线条）。
- **红砖端翼**（两端红墙白框）+ 深色横向窗带。
- 中部**玻璃顶中庭连廊**（半透明天棚），其下为主入口。
- 选致远楼而非笃行楼是设计者的选择（用户未指定具体楼栋），用户已认可。

**一楼内部（rev.2，布局为设计者方案，无实景依据）**：
- 开放段：中央 x∈[-18,+18] 共 36m；两翼一层实心。
- 主入口：中央 z=+8 外墙，门洞净宽 3m、净高 2.6m，直通走廊；室内外同标高（无台阶）。
- 走廊：沿 x 向，净宽 2.4m，连通主入口与三间教室。
- 教室 3 间：每间净宽 9m × 净深 7m，门洞净宽 1.2m（朝走廊），有窗户（半透明玻璃片）。
- 每间教室家具：3 排 × 4 列课桌椅（桌面 1.2×0.5m、高 0.75m；椅 0.45×0.45m、高 0.45m）、讲台（1.6×0.8m、高 0.9m）、黑板（4×1.2m，挂前墙，深绿近黑）。
- 每间教室灯具：2 根 1.2m 长条日光灯管（发光片，吊高 3.2m）+ 1 个居中 PointLight；共 3 个 PointLight、6 根灯管。
- 一层净高 3.6m，层高 3.9m；二至五层为整体实心体量。

### 3.3 天工体育场（`campus:sports-field`，label「天工体育场（操场）」）
官方图集无操场照片；名称有学生视频佐证（「图书馆视角下的天工体育场」）。以下为**标准 400m 田径场的通用构造 + 设计者的推断**，做错的具体特征由用户指出后修正：
- 红色塑胶环形跑道（stadium 形：两直道 + 两半圆），白色分道线，8 道。
- 内场绿色足球场（105×68m）含白线、中圈、两个球门。
- 一侧带顶棚看台（阶梯排 + 立柱 + 顶棚）与中央主席台、12m 旗杆红旗。
- 跑道/球场为贴地薄片（约 0.05m 厚），人物直接站立在世界地面上，可自由跑动。

## 4. 尺寸（米，估算值，以真实规格反推）

| 素材 | 宽(x) | 高(y) | 深(z) | 依据 |
|---|---|---|---|---|
| east-gate | 36 | 13 | 8 | 中央拱门净宽 8m（双车道）、净高 6m；三重檐总高约 13m |
| zhiyuan-building | 80 | 21 | 16 | 5 层教学板楼（层高 3.9m + 女儿墙），航拍长宽比估算 |
| sports-field | ≈186 | ≈12（旗杆为最高点；看台顶棚约 8–10m） | ≈100 | 标准 400m 八道田径场跑道外沿约 176×92m，另含看台出挑 |

以上均为估算并在代码注释中标注「估算」；包络测试按 ±15% 宽容区间，不追求测绘精度。
**操场远超默认单区块世界（54×42m），用户须先扩地**——放置器本身支持扩地后的大世界，无需改引擎。

## 5. 技术方案与约束

- **只读约束**：`sceneAssetGeneratorRegistry.js` 不得修改。新生成器放独立模块 `src/three/world/campus/ncgxyLandmarkGenerators.js`（纯函数 `create…(THREE, dimensions)` 返回 Group），适配层对 `campus` 类别直接调用该模块、绕开注册表；其余流程（目录校验、尺寸表、componentId 标注、碰撞规则表、分析器门禁）全部复用现有适配层机制。
- `BUILTIN_CATEGORY_LABELS` 增加 `campus: '校园地标'`；目录 13→16 件；`BUILTIN_ASSET_DIMENSIONS`、`COLLISION_RULES` 各增三条。既有目录测试「5 类 13 个」按本设计更新为「6 类 16 个」（测试意图随特性演进，非放松断言）。
- 根 `userData.sceneAsset`、assetName、builtinAssetRef 等身份字段与现有 13 件一致；`proceduralModelSource = null`（不可入库归档的规则不变）。
- **匾额文字**：用 CanvasTexture 书写「南昌工学院」金色字（浏览器端）。Node 测试环境无 2D canvas，生成器必须显式守卫降级为无字黑匾，且降级路径有独立测试；浏览器路径的测试通过注入的假 2D 上下文验证贴图被使用。ObjectLoader 对 CanvasTexture 走图像 dataURL 序列化，存档/刷新可存活。
- **跑道几何**：THREE.Shape（absarc 圆弧 + 直线）挖洞挤出成环，贴地平放；分道线为窄环带。纯几何运算，Node 测试可直接断言包围盒与跑道外沿尺寸。
- **教室灯光（rev.2）**：复用路灯已验证的接线契约——根 `userData.proceduralModelEnvironmentBindings`，每个 PointLight 一条 `intensity` 绑定（enabledValue 约 1.6 / disabledValue 0 / defaultValue true），每根灯管一条 `visible` 绑定（灯管为 MeshBasicMaterial，无 emissiveIntensity，必须用 visible）；variable 均为 `lighting.artificial.enabled`。PointLight 带 componentId 与 `collisionPolicy:'none'`、castShadow=false；绑定目标 id 受静态合批保护（既有机制）。
- **碰撞规则**（进入 COLLISION_RULES，语义命名沿用 `${category}-${objectType}-${semantic}-${seq}` 约定）：
  - east-gate：门墩 required；屋顶×3、匾额、门楣装饰 none。拱门洞无任何碰撞体，玩家可穿行。
  - zhiyuan-building：一层外墙分块（窗下墙/窗间柱/门旁墙/门上梁）、内部隔墙、两翼实心体、二至五层体量、柱廊立柱、课桌、椅子、讲台 required；连廊玻璃顶、雨棚、窗玻璃、黑板、灯管 none；PointLight none。门洞与走廊、教室净空处无任何碰撞体。
  - sports-field：跑道、球场、标线、旗帜 none；球门框立柱、看台阶梯体、旗杆 required；看台顶棚 none。看台不可登临（阻挡体），操场其余区域全部可行走。
- east-gate 与 sports-field 无 PointLight、无环境绑定；既有「非路灯无灯无绑定」护栏测试的例外清单更新为 lamp + zhiyuan-building（spec 明示的测试意图更新）。
- 全部静态网格，合批友好；三件合计三角总量预算 < 4 万（教室家具使预算上调）；PointLight 全项目新增仅 3 个。

## 6. 面板与放置体验

- 「内置素材」区新增第六个分类组「校园地标」，排序在现有五类之后。
- 目录条目支持可选 `note` 字段并渲染在卡片上；sports-field 的 note：「真实 400m 操场，占地约 186×100 米，需先扩地再放置」；zhiyuan-building 的 note：「一楼可进入，含 3 间教室，灯光受人工灯光总开关控制」。
- 放置、变换、删除、存档/恢复完全复用既有链路，无新交互。

## 7. 测试策略（沿用适配层既有模式）

1. 目录测试更新：6 类 16 件、新三件中文标签、note 字段存在性。
2. 每件新素材：部件标注与 collisionPolicy 断言、真实尺寸包络、分析器 complete 零 issue（既有 it.each 自动覆盖）。
3. east-gate：中央拱门下方无碰撞体（门洞可通行）；匾额两条路径（有/无 2D 上下文）。
4. zhiyuan-building：红砖端翼与柱廊存在且 required；课桌/椅/讲台 required；用既有 `modelTraversalTester` 验证角色能经主入口门洞进入走廊并进入至少一间教室（该 tester 已有「经真实门洞进楼」用例模式）；3 个 PointLight 标注 none 且驱动真实 `applyEnvironmentBindings` 关/开双向（灯光 intensity 与灯管 visible 联动）；开放段两翼实心不可穿。
5. sports-field：跑道外沿尺寸≈176×92（不含看台出挑）；球场 105×68；可行走区域无 required 部件。
6. 全量回归 + build，基线红名单不变。

## 8. 留给实现者的决定

- 具体网格拆分粒度、瓦顶檐口的几何近似方式（斜盒/挤出多边形均可，以轮廓像为准）。
- 看台排数、柱廊间距、课桌椅精确摆位等重复结构的循环参数（在 §3 给定净尺寸内）。
- 外墙窗洞分块的具体划分方式（保证门洞/窗洞净空即可）。
- 材质色号可在 §3 特征描述范围内微调，以低多边形整体观感为准。
